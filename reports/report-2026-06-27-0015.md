## ملخص تنفيذي

المشروع هو Monorepo احترافي بثلاثة تطبيقات مستقلة (Portfolio — Nuxt 4، API — Express.js، Dashboard — Nuxt 4). المعمارية العامة سليمة والفصل بين التطبيقات واضح، وتوثيق التصميم (`DESIGN.md`) و`CLAUDE.md` بمستوى عالٍ نادر في المشاريع الشخصية. الكود عموماً نظيف ومنظّم ويتبع معايير Nuxt 4 الحديثة.

أبرز المشكلات تتركّز في:

- **استخدام TypeScript جزئي** في الـ Client (ملفات `.js` في composables وserver routes بدلاً من `.ts`)، وفي الـ Server بالكامل `.js` بدون أي typing.
- **تعارض إصدارات Nuxt UI** بين `client` (`4.5.1`) و`db` (`4.6.1`) قد يسبب تباين في السلوك.
- **ضعف اختبارات** — لا توجد اختبارات وحدة (unit tests) في الـ client أو الـ server؛ Playwright موجود لكن لـ E2E فقط.
- **نقاط أمان** في الـ Server: استخدام `eval`-style في CSP لـ `'unsafe-eval'`، و`methodNotAllowed` يقرأ `allowedMethods` قبل تعريفها في بعض الـ routes.
- **ملاحظات أداء** — الـ Client يستخدم `useFetch` في `useAPI` بشكل صحيح، لكن `blog.get.js` في server routes يستخدم `fetch` بدلاً من `$fetch` مما يفقده ميزة deduplication.

التقييم العام: **المشروع في حالة جيدة وقابل للإنتاج، مع مجال واضح للتحسين في typing، اختبارات، وتحسينات أمان محدودة.**

### المهمة 2: جودة الكود والمعمارية (Server)

**الهدف:** تقييم الـ Express API، البنية، الـ middleware، والـ controllers.

**أبرز النتائج:**

- 🟠 **الـ Server بالكامل JavaScript بدون TypeScript** — جميع الملفات `.js` (models, controllers, routes, utils). القاعدة تقول "TypeScript everywhere، No plain .js files". هذا أكبر انحراف عن معايير المشروع.
- 🟢 **بنية middleware احترافية** — [app.js](file:///f:/Code/personal/Clients/Beingmomen/apps/server/app.js) يستخدم `helmet`، `rateLimit`، `mongoSanitize`، `hpp`، `compression`، `cookieParser`، وcorrelation IDs. طبقات أمان متعددة بشكل صحيح.
- 🟢 **`handlerFactory` نمط ممتاز** — [handlerFactory.js](file:///f:/Code/personal/Clients/Beingmomen/apps/server/controllers/handlerFactory.js) يلخص CRUD operations بشكل DRY. تصميم نظيف.
- 🟡 **`updateOne` في `handlerFactory` يرسل response قبل `next()`** — في [handlerFactory.js:61-67](file:///f:/Code/personal/Clients/Beingmomen/apps/server/controllers/handlerFactory.js#L61-L67)، `res.status(200).json(...)` يُستدعى ثم `next()` لو `nextStep=true`. هذا يعني أن الـ response أُرسلت ثم middleware قد يحاول التعديل عليها → headers already sent error.
- 🟡 **`methodNotAllowed` يقرأ `allowedMethods` قبل تعريفه** — في [userRoutes.js:11](file:///f:/Code/personal/Clients/Beingmomen/apps/server/routes/userRoutes.js#L11)، الدالة `methodNotAllowed(allowedMethods)` تستخدم `allowedMethods.join(...)` لكن المعامل `allowedMethods` هو parameter name يطابق المتغير الخارجي. هذا يعمل لكنه ضعيف القراءة وقد يسبب bugs لو تغير الاسم.
- 🟢 **`authController` متين** — [authController.js](file:///f:/Code/personal/Clients/Beingmomen/apps/server/controllers/authController.js) يطبق: bcrypt hashing (cost 12)، JWT cookie httpOnly + sameSite=strict + secure in production، password changed check، email enumeration prevention في forgotPassword، auth rate limiter (10 attempts/15min).
- 🟢 **`APIFeatures` مع حماية ReDoS** — [apiFeatures.js:46](file:///f:/Code/personal/Clients/Beingmomen/apps/server/utils/apiFeatures.js#L46) يهرب special regex characters في search. و`paginate` يضع `MAX_LIMIT = 100`. ممتاز.
- 🟡 **`errorController` في dev mode يرسل تفاصيل خطأ كاملة** — [errorController.js](file:///f:/Code/personal/Clients/Beingmomen/apps/server/controllers/errorController.js) يرسل stack traces في dev. هذا صحيح، لكن يجب التأكد أن `NODE_ENV=production` في الـ deployment.
- 🔵 **DNS servers مُ hardcoded إلى Google** — في [server.js:4](file:///f:/Code/personal/Clients/Beingmomen/apps/server/server.js#L4) `dns.setServers(['8.8.8.8', '8.8.4.4'])`. قد يكون مقصوداً لتفادي DNS issues في الـ VPS، لكن يستحق تعليقاً يوضّح السبب.
- 🔵 **`start:prod` script يستخدم `nodemon`** — في [package.json:7](file:///f:/Code/personal/Clients/Beingmomen/apps/server/package.json#L7) `"start:prod": "NODE_ENV=production nodemon server.js"`. استخدام nodemon في production غير مثالي — استخدم `node server.js` مباشرة.
- 🟡 **تكرار في ملفات controllers** — ملفات مثل `_blogController.js` و`_faqController.js` و`_experienceController.js` تبدأ بـ `_`. الـ prefix `_` قد يعني "private" لكنها مستوردة في routes. التسمية مربكة.

**التوصيات:**

- نقل الـ Server إلى TypeScript تدريجياً (ابدأ بـ utils وmodels).
- إصلاح `updateOne` في `handlerFactory` لمنع double-response.
- استبدال `nodemon` بـ `node` في `start:prod`.
- توثيق سبب hardcoded DNS servers.

### المهمة 4: الأمان

**الهدف:** فحص الأمان شاملاً (auth, secrets, validation, headers, deps).

- 🟡 **`blog.get.js` يستخدم `fetch` بدلاً من `$fetch`** — [blog.get.js:6](file:///f:/Code/personal/Clients/Beingmomen/apps/client/server/api/blog.get.js#L6) يستخدم `fetch()` العادية بدلاً من `$fetch` أو `useFetch`. هذا يفقده deduplication ويعمل double request في SSR.
- 🟢 **الـ Server rate limiting ممتاز** — 10000 req/hour عام + 10 req/15min لـ auth endpoints. (الملف: [app.js:78-84](file:///f:/Code/personal/Clients/Beingmomen/apps/server/app.js#L78-L84))

- 🟢 **input validation شامل** — [common.js](file:///f:/Code/personal/Clients/Beingmomen/apps/server/middleware/validators/common.js) يطبق `escape()`, `normalizeEmail()`, regex validation على phone. استخدم `express-validator` بشكل صحيح.
- 🟢 **password hashing بـ bcrypt cost 12** — [userModel.js:79](file:///f:/Code/personal/Clients/Beingmomen/apps/server/models/userModel.js#L79). مناسبة.
- 🟢 **JWT cookie httpOnly + sameSite=strict + secure in prod** — [authController.js:24-30](file:///f:/Code/personal/Clients/Beingmomen/apps/server/controllers/authController.js#L24-L30). ممتاز.

- 🟢 **`upload.post.ts` يتحقق من file type وsize** — [upload.post.ts:21-29](file:///f:/Code/personal/Clients/Beingmomen/apps/client/server/api/upload.post.ts#L21-L29) يحدّ من الـ types و5MB max. جيد.

**التوصيات:**

### المهمة 5: الأداء والبناء

- 🟡 **Server: تعارض `eslint` configs** — يوجد `.eslintrc.json` و`.eslintrc.js` معاً في `apps/server/`. هذا يسبب تضارب.
- 🔵 **Server: تبعيات غير مستخدمة** — `@ngrok/ngrok` و`ngrok` (beta) في dependencies. إن لم تُستخدم في production، انقلها إلى devDependencies.

**التوصيات:**

- توحيد `@nuxt/ui` على إصدار واحد (`^4.6.1` لكلا التطبيقين).
